## Return-Pathとは？

Return-Pathとは、バウンスメッセージが送られる先のアドレスです。バウンスメッセージとは、メールを配信できなかったときにサーバーが送る自動の通知です。

すべてのメールには、2つの送信者アドレスがあります。1つ目は**From**アドレスです。読み手が受信トレイで目にする名前とアドレスです。2つ目が**Return-Path**です。読み手には表示されません。メールサーバーが使います。

紙の手紙で考えてみます。封筒の中の手紙には、一番上に差出人の名前があります。それがFromアドレスです。封筒の隅には差出人の住所があります。郵便局がそれを使うのは、手紙を配達できないときだけです。それがReturn-Pathです。

Return-Pathは、エンベロープの送信者（envelope sender）やバウンスアドレスとも呼ばれます。送信側のサーバーは、配信の最初に、受信側のサーバーにこのアドレスを伝えます。受信側のサーバーは、それをメールの先頭にある `Return-Path:` で始まる行に書き込みます。

## 簡単な例

メールがバウンスしたときのReturn-Pathの働きは次のとおりです。

1. **トムがニュースレターを送ります。**トムはパン屋を経営しています。メール配信サービスを通じて、毎月ニュースレターを送っています。メール配信サービスとは、利用者の代わりに大量のメールを送る会社です。
2. **2つのアドレスが設定されます。**Fromアドレスはtom@bakery.exampleです。配信サービスは、Return-Pathを配信サービス自身のバウンス用アドレス、たとえばbounces@mail.provider.exampleに設定します。
3. **顧客の1人が転職しています。**リストにいる顧客の1人が転職しました。古いアドレスはもう存在しません。
4. **バウンスはReturn-Pathに届きます。**受信側のサーバーは、バウンスの通知をトムではなくbounces@mail.provider.exampleに送ります。
5. **配信サービスが対応します。**配信サービスはバウンスを読み、そのアドレスへの送信を止めます。トムがその通知を目にすることはありません。

ニュースレターのバウンスが自分の受信トレイに届かないことが多いのは、このためです。バウンスはReturn-Pathに届き、配信サービスが処理します。

## Return-PathとFromアドレスの違い

| | Fromアドレス | Return-Path |
|---|---|---|
| **誰が見るか** | 読み手（受信トレイで） | メールサーバー |
| **誰が設定するか** | 送信者自身、またはメールアプリ | 送信側のサーバー |
| **何のためか** | 誰がメールを送ったかを示す | バウンスメッセージを受け取る |
| **SPFで確認されるか** | されません | されます |

2つのアドレスが同じこともあります。GmailやOutlookから普通のメールを送る場合は、通常同じです。配信サービスを通じて送る場合は、通常異なります。

## メールのReturn-Pathを確認する方法

メールの完全なヘッダーを開きます。Gmailでは、メールを開き、3つの点をクリックして**「メッセージのソースを表示」**を選びます。Outlookでは、メッセージのプロパティを開きます。上のほうで、次のような行を探します。

`Return-Path: <bounces@mail.provider.example>`

## SPFとDMARCで重要な理由

[SPF](/glossary/spf)は、ドメインのメールを送ってよいサーバーを一覧にした、ドメインのルールです。SPFはReturn-Pathのドメインを確認します。Fromアドレスは確認しません。

[DMARC](/glossary/dmarc)は、2つ目の確認を加えます。SPFに合格したドメインが、Fromアドレスのドメインと一致しているかを確認します。配信サービスが自身のReturn-Pathドメインを使っている場合、SPFは配信サービスのドメインで合格しても、Fromのドメインとは一致しないことがあります。

多くの配信サービスでは、Return-Pathを送信者自身のドメインに設定できます。これはカスタムバウンスドメインと呼ばれることがよくあります。これを使えば、SPFは自社のドメインで合格し、DMARCはその結果を数えることができます。

**例：**トムのFromアドレスはbakery.exampleにあります。配信サービスで、Return-Pathをbounces.bakery.exampleに設定できます。これで、SPFに合格するドメインとFromアドレスのドメインが一致します。

## 検証ツールでできること

リストからのバウンスは、すべてReturn-Pathに届きます。配信サービスはその数を数えています。返ってくるバウンスが多すぎると、多くの配信サービスはアカウントを一時停止したり、リストをクリーニングするよう求めたりします。

[メールアドレスチェッカー](/email-checker)は、何かを送る前に、アドレスが存在するかを受信側のサーバーに確認します。使われていないアドレスを先に削除するので、Return-Pathに届くバウンスはずっと少なくなります。
