メールの運用で、到達率の急な低下ほど影響の大きいものはあまりありません。ある朝まではキャンペーンに普段どおりの反応があったのに、翌日には開封率がゼロ近くまで下がり、返信がなくなります。送信キューには、次のような拒否の通知がたまっていきます。

```text
550 5.7.1 Service unavailable; client [198.51.100.24] blocked using zen.spamhaus.org
554 5.7.1 Access denied; sender IP listed in Barracuda Reputation Network
```

受信側のメールサーバーが、件名や本文を見る前にメッセージを拒否している場合、送信元のIPアドレスかドメインが、DNSを使ったブラックリスト（DNSBL）に載っています。DNSBLは、メールのブラックリストやRBLとも呼ばれます。

ブラックリストへの掲載は、一時的なコンテンツのフィルターではありません。ネットワークの段階での直接のブロックです。主な受信側のネットワーク（Google Workspace、Microsoft 365、Yahoo Mail、企業のメールゲートウェイなど）は、SMTPの最初のやり取り（ハンドシェイク）の間に、このリアルタイムのデータベースを照会します。送信元の識別子に印が付いていると、接続はその場で切られます。

この記事では、メールのブラックリストのしくみ、主なスパム対策のデータベースにドメインやIPが載っているかを確認する方法、解除申請を通す方法、そして送信者レピュテーションをくり返しの掲載から守る方法を説明します。

## ブラックリストによるブロックと迷惑メールフィルターの違い

原因を調べる前に、ブラックリストへの掲載なのか、受信側の迷惑メールフォルダへの振り分けなのかを見分けておくと役に立ちます。

| 項目 | DNSBL / RBLのブラックリスト | メールボックスプロバイダーの迷惑メールフィルター |
| --- | --- | --- |
| **判定のタイミング** | SMTPの最初のやり取り（接続の段階） | 配信後の分析（受信トレイへの振り分け） |
| **サーバーの応答** | ハードバウンス（コード`550`または`554`）か、接続の切断 | コード`250 OK`で受け付け |
| **受信者から見えるもの** | メールはまったく届かない | メールは受信者の迷惑メールフォルダに入る |
| **影響の範囲** | そのDNSBLを使うすべてのメールサーバー | 1つのメールボックスプロバイダーだけ（たとえばGmailだけ） |
| **主な原因** | スパムトラップへの送信、高いバウンス率、オープンリレー | 受信者の反応が少ない、スパムのような文面、SPFやDKIMの未設定 |
| **解決の方法** | ブラックリストの運営者への正式な解除申請 | ドメインのウォームアップ、リストの整理、レピュテーションの回復 |

メッセージが迷惑メールフォルダに入っていても、メールサーバーのログでは配信ステータスが`250 OK`になっている場合、ドメインはDNSBLのブラックリストには載っていません。受信側のメールボックスプロバイダーが、アルゴリズムによるレピュテーションのスコアをもとに、メッセージを振り分けています。

メールサーバーが、特定のブラックリストのホスト名を示したハードな拒否を受け取っている場合は、DNSBLに掲載されています。すぐに対処が必要です。

## メールのドメインやIPがブラックリストに載っているかを確認する方法

ブラックリストへの掲載を確認するには、DNSBLのサーバーを照会し、送信IPやドメインに該当するレコードが返るかを調べます。確認には、複数のRBLをまとめて調べる自動のスキャナーを使う方法と、ターミナルから手動でDNSを照会する方法があります。

### 1. 複数のRBLを調べる自動のスキャナー

複数のRBLを照会するサービスは、数十の公開ブラックリストを数秒でまとめて調べます。信頼できる主な無料のスキャナーは次のとおりです。

- **MXToolbox Blacklist Check**：送信IPやドメイン名について、100以上のDNSBLを調べます。
- **DNSChecker Email Blacklist**：50以上のDNSBLとSURBLのデータベースを、すばやくまとめて照会します。
- **MultiRBL（valli.org）**：開発者向けの軽い照会ツールで、200以上のブラックリストを照会します。

スキャンするには、送信IPアドレス（オフィスのWi-FiではなくメールサーバーのIP）か、送信ドメイン（例：`company.com`）を入力します。

```youtube
wOIJHhHZt04
動画：[How To Use Email Blacklist Checker or Spam Database Lookup Tool](https://www.youtube.com/watch?v=wOIJHhHZt04)（InboxAlly: Mastering Email Deliverability）
```

### 2. コマンドラインでの手動のDNSBLチェック（システム管理者向け）

ウェブの自動の照会ツールは便利です。一方、`dig`や`nslookup`で手動で照会すると、ブラックリストの運営者の権威ネームサーバーから、キャッシュされていない結果を直接得られます。

DNSを使うブラックリストは、[IETF RFC 5782](https://datatracker.ietf.org/doc/html/rfc5782)に従い、IPアドレスを逆順にした表記を使います。手動で照会する手順は次のとおりです。

1. 送信元のIPv4アドレスの4つの数字（オクテット）を逆順にします。たとえば、メールサーバーのIPが`198.51.100.24`なら、逆順の文字列は`24.100.51.198`です。
2. DNSBLのルートドメイン（例：`zen.spamhaus.org`）を後ろに付けます。
3. `dig`で、通常の`A`レコードのDNS照会を実行します。

```bash
# Query Spamhaus ZEN for IP 198.51.100.24
dig +short 24.100.51.198.zen.spamhaus.org

# Query Barracuda Reputation Block List (BRBL)
dig +short 24.100.51.198.b.barracudacentral.org

# Query SpamCop (SCBL)
dig +short 24.100.51.198.bl.spamcop.net
```

#### 返ってくるコードの読み方

- **応答なし / `NXDOMAIN`**：IPに問題はありません。そのブラックリストには、そのアドレスについての記録がありません。
- **`127.0.0.X`の応答**：IPが掲載されています。最後の数字が掲載の種類を示します。

```text
127.0.0.2 -> SBL (Spamhaus Block List: Verified spam source or trap hit)
127.0.0.4 -> XBL (Exploit Block List: Compromised server, malware, or open proxy)
127.0.0.10 -> PBL (Policy Block List: Residential/dynamic IP that should not send direct MX mail)
```

上のブロックの意味は次のとおりです。`127.0.0.2`はSBL（確認されたスパムの送信元か、トラップへの送信）、`127.0.0.4`はXBL（乗っ取られたサーバー、マルウェア、オープンプロキシ）、`127.0.0.10`はPBL（MXへ直接メールを送るべきではない、家庭用や動的なIP）です。

送信IPではなくドメイン名が、ドメインのブラックリスト（DBL）に載っているかを確認するには、ドメイン名を直接照会します。

```bash
# Query Spamhaus Domain Blocklist (DBL)
dig +short company.com.dbl.spamhaus.org
```

`127.0.1.2`が返った場合、ドメイン名そのものがスパムのドメインとして掲載されています。この場合、送信IPを変えても、メールプロバイダーはメッセージを拒否します。

## 本当に重要な5つのブラックリスト

インターネットには、公開と非公開を合わせて数百のメールのブラックリストがあります。しかし、メールが受信トレイに届くかどうかを実際に左右するのは、そのうちのごく一部です。

小規模なブラックリストや影響力のないブラックリスト（個人が運営するリストや、有料の削除を求める悪質なサービスなど）の多くは、主なメールボックスプロバイダーに無視されています。ほとんど使われていないリストに載っても、到達率は下がりません。

注意を向けるべき主なリストは次のとおりです。

### 1. Spamhaus（ZEN：SBL、XBL、CSS、DBL）

Spamhausは、世界で最も影響力のあるスパム対策の組織です。そのデータは、世界で30億以上のメールボックスを守っています。大手の通信ネットワーク、Fortune 500企業のメールゲートウェイ、個人向けのメールプロバイダーも含まれます。

- **SBL（Spamhaus Block List）**：確認されたスパムの送信元、同意を確認していないメーリングリスト、スパムトラップに送信している送信者が対象です。
- **XBL（Exploit Block List）**：第三者に悪用されたサーバー、ボットネット、マルウェアに感染したサーバーが対象です。
- **DBL（Domain Block List）**：スパムのメッセージ、フィッシングの誘導、防弾ホスティング（苦情を受けても削除に応じないホスティング）で見つかったドメインを掲載します。
- **ZEN**：SBL、SBLCSS、XBL、PBLの記録をまとめた統合ゾーンです。

Spamhausへの掲載は、すぐに対応が必要な緊急事態です。世界中の主な企業のメールサーバーやインターネットサービスプロバイダーで、配信がブロックされます。

### 2. Barracuda（BRBL）

Barracuda Reputation Block List（`b.barracudacentral.org`）は、Barracuda Networksが運営しています。企業のネットワークの中で動いている数千台のBarracuda Email Security Gatewayの機器から集めた通信のデータをもとに作られています。

B2Bのコールドメールや企業向けのマーケティングメールを送っている場合、Barracudaに掲載されると、オンプレミスやクラウドのBarracudaのセキュリティフィルターを使う企業の受信者で、すぐにバウンスが増えます。

### 3. SpamCop（SCBL）

SpamCopは、報告をもとにした最も古いブラックリストの一つ（`bl.spamcop.net`）を運営しています。受信者がメールをスパムとして報告したときや、自動のトラップに不要なメッセージが届いたときに、送信者が自動で掲載されます。

Spamhausと違い、SpamCopの掲載は短期間で変わります。スパムの苦情がしきい値を下回れば、掲載は通常24〜48時間で自動で解除されます。

### 4. Invaluement（ivmURI、ivmSIP）

Invaluementは、企業向けの有料のレピュテーションデータベースです。大量のメールを扱う企業のフィルターやセキュリティソフトでよく使われています。スノーシュースパム（スパムを多くのIPアドレスに分散して送る手口）をすばやく見つけることと、ドメイン単位のURLのレピュテーションを追跡することで知られています。

### 5. UCEPROTECT Level 3を無視してよい理由

複数のRBLを調べるツールを使うと、**UCEPROTECT Level 3**に赤い掲載の表示が出て、送信者があわてることがよくあります。

UCEPROTECT Level 3は、個別の送信IPではなく、サブネットや自律システム番号（ASN）全体を掲載します。同じクラウドホスティング（DigitalOcean、AWS、Linode、Hetznerなど）の無関係な顧客がスパムを送ると、UCEPROTECTはそのホスティング全体で、問題のない近くのIPアドレスを数千件まとめて掲載します。

このように無関係なIPまで大きく巻き込むため、主なメールプロバイダー（Google、Microsoft、Yahooなど）は、配信の判断にUCEPROTECT Level 3を使っていません。到達率の専門家やメールサーバーの管理者も、Level 3への掲載はほとんど気にしていません。削除にお金を求めるサービスに、解除の料金を払わないでください。

## ブラックリストの解除の手順

ブラックリストのチェックで、主なデータベースに掲載されていることがわかったら、次の4つの手順で回復します。

```
[ Step 1: Halt Outbound Queues ]
             │
             ▼
[ Step 2: Audit Root Cause & Logs ]
             │
             ▼
[ Step 3: Implement Technical Fixes ]
             │
             ▼
[ Step 4: Submit Delisting Request ]
```

上の図の4つの手順は、送信の停止、根本原因とログの確認、技術的な修正、解除申請の送信です。

### 手順1：送信をすぐに止める

メールサーバーがまだメッセージを送っている間は、解除の申請を出さないでください。サーバーがまだスパムトラップに送信していたり、バウンスを出していたりする間に削除を求めると、申請は却下されます。さらに、そのIPは協力しない常習の違反者として扱われます。

- 自動の送信シーケンスとコールドメールのキャンペーンを止めます。
- メールサーバーのキュー（Postfixでは`mailq`）を確認し、乗っ取られたアカウントや脆弱なお問い合わせフォームによる大量のスパム送信がないかを調べます。

### 手順2：根本原因を見つけて直す

ブラックリストは、きっかけとなる出来事がなければIPを掲載しません。ログとインフラを確認し、次の4つのよくある原因のどれが掲載につながったかを調べてください。

1. **プリスティン（pristine）スパムトラップ**：人が一度も使ったことのないアドレスにメールを送りました。このアドレスは、ウェブをスクレイピングするボットを捕まえるためだけに公開されています。リードのリストを購入した場合や、ウェブサイトの連絡先のページを検証せずにスクレイピングした場合は、このトラップに送信した可能性が高いです。
2. **高いバウンス率**：送信のバウンス率が2.0%〜5.0%を超えました。古い連絡先、検証していない連絡先、でたらめな連絡先が含まれていることを示します。
3. **認証情報の漏えい**：サーバーのユーザーアカウントが侵入され、フィッシングやスパムの中継に使われました。
4. **認証の設定がない**：ドメインに整合したSPFとDKIMのレコードがなく、第三者がドメイン名をなりすませる状態です。

### 手順3：主な運営者に削除を申請する

問題を解決し、ログに問題がなくなったら、公式の窓口から正式な解除申請を出します。

#### Spamhausの削除
1. 公式の[Spamhaus IP and Domain Reputation Checker](https://check.spamhaus.org/)を開きます。
2. 掲載されているIPアドレスかドメインを入力します。
3. Spamhausが示す掲載のコードと説明を確認します。
4. **Request Removal**ボタンをクリックし、確認用のフォームに入力します。
5. ドメインの、使われている管理用のメールアドレスを入力します。問題のない送信者の初めての削除は、通常1〜4時間で処理されます。

#### Barracudaの削除
1. [Barracuda Central Reputation System](https://www.barracudacentral.org/lookups)を開きます。
2. メールサーバーのIPアドレスを入力します。
3. **Barracuda Removal Request**のフォームに進みます。
4. 連絡先を入力し、行った対策をはっきりと事実に沿って説明します。通常、処理には12〜24時間かかります。

#### SpamCopの削除
- [SpamCop](https://www.spamcop.net/bl.shtml)では、手動の申請はほとんど必要ありません。問題のあるメールの送信を止めていれば、最後に苦情が報告されてから24〜48時間で、SpamCopが自動で掲載を解除します。

### 解除の申請に書くべきこと（書いてはいけないこと）

解除の申請は、経験のあるネットワークエンジニアが確認します。申請の書き方で、承認されるかどうかが決まります。

> **書いてはいけない例：**  
> *「当社は正当な企業で、これは緊急の誤りです。損害が出ています。すぐに当社のIPを削除してください。」*  
> （技術的な安心材料が何もないため、後回しにされます。）

> **書くべき例：**  
> *「10月24日にアップロードした検証していないマーケティングリストが、バウンスと苦情の急増を引き起こしたことを確認しました。送信はすぐに止めました。検証していないレコードはすべて削除し、送信前に無効なアドレスと使い捨てのアドレスを取り除く自動のリストのチェックを導入しました。SPFとDKIMの整合も確認しました。送信キューに問題はありません。」*

## ブラックリストにもう載らないようにする方法

解除されただけでは、対策は半分しか終わっていません。送信のやり方が変わらなければ、ドメインは数日のうちに同じブラックリストにまた載ります。

送信者レピュテーションを守るには、次の3つの対策を続ける必要があります。

### 1. メールの認証を厳しく設定する

認証されていないメールは、ドメインのなりすましに弱くなります。スパムの送信者がフィッシングのキャンペーンで`From:`ヘッダーにドメイン名を使うと、ドメインのレピュテーションが下がります。

- **SPF（Sender Policy Framework）**：ドメインの代わりにメールを送ってよいメールサーバーを明示します。無料の[SPFチェッカー](/spf-checker)で設定を確認できます。
- **DKIM（DomainKeys Identified Mail）**：送信するすべてのメッセージに、2048ビットの鍵で暗号の署名を付けます。[DKIMジェネレーター](/dkim-generator)で、正しいDNS用の鍵を作れます。
- **DMARC**：ドメインから送られたと名乗る不正なメッセージを拒否するよう、受信側のサーバーに指示します。

### 2. バウンス率とSMRのデータを監視する

バウンス率は必ず2.0%未満に保ってください。3.0%を超えるバウンス率は、リストの管理が不十分であることを示します。5.0%を超えると、企業のフィルターで自動のブラックリスト掲載につながります。

- 過去の配信の数値は、[バウンス率計算ツール](/bounce-rate-calculator)で計算し、比較できます。
- 一時的なサーバーの問題と、恒久的に無効なアドレスを見分けるには、[ハードバウンスとソフトバウンスの違い](/blog/hard-bounce-vs-soft-bounce)の解説をお読みください。

### 3. 送信の前にすべてのリードのリストをクリーニングする

メールのブラックリストへの掲載の85%以上は、プリスティンスパムトラップへの送信か、削除されたメールボックスへのくり返しの送信が原因です。

スクレイピングした見込み客のリスト、古いCRMのデータベース、ウェビナーの登録者には、ドメインの入力ミス、一時的な使い捨てのアドレス、放置されてスパムトラップとして再利用されたアドレスがよく含まれています。

連絡先のリストを送信ツールやコールドメールのツールにインポートする前に、専用の検証でアドレスを確認してください。アドレス1件ずつなら[無料のメールアドレス存在確認ツール](/email-checker)で確認でき、使い捨てのドメインは[捨てメアド判定ツール](/disposable-email-checker)で見つけられます。リストをクリーニングすると、存在しないドメイン、構文の誤り、一時的なメールのプロバイダー、既知のトラップのネットワークを、メールサーバーが扱う前に取り除けます。

## よくある質問

### ブラックリストの解除が反映されるまで、どのくらいかかりますか？
運営者が解除の申請を承認すると、運営者の権威DNSBLサーバーはほぼすぐに更新されます。ただし、受信側のメールサーバーはDNSのレコードを手元にキャッシュしています。受信側のサーバーのDNSのTTL（Time to Live）の設定によりますが、すべてのネットワークで通常の配信に戻るまで、一般に2〜24時間かかります。

### Google WorkspaceやSendGridのような信頼できるESPを使っていても、ドメインがブラックリストに載ることはありますか？
はい。メール配信サービス（ESP）はインフラを扱いますが、送信先のアドレスの責任は送信者にあります。Google WorkspaceやSendGridでコールドメールや検証していない大量のリストを送り、スパムトラップに送信すると、Spamhausがその送信ドメインをDomain Blocklist（DBL）に掲載することがあります。そうなると、どの送信サービスを使っていてもメールは拒否されます。

### ドメインがブラックリストに載ったら、ドメイン名を変えるべきですか？
いいえ。ブラックリストに載ったドメインを捨てて新しいドメインを登録するのは間違いです。新しいドメインには送信者レピュテーションがまったくなく、メールボックスプロバイダーから厳しい送信量の制限やグレーリスティングを受けます。根本原因を直し、購読者のリストをクリーニングし、今のドメインで正式な解除の手続きを終えるほうが早く、長期的な到達率にも良い結果になります。
