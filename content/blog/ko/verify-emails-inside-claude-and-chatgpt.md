이메일 검증은 대부분 아직도 2015년과 같은 방식으로 이루어집니다. CSV를 내보내고, 브라우저 탭을 열고, 파일을 업로드하고, 기다립니다. 그리고 다른 CSV를 내려받아 어딘가에 가져옵니다. 이 방법으로도 검증은 됩니다. 하지만 알고 싶은 것은 “이 메일함이 실제로 있는가”라는 질문 하나인데, 작업을 네 번이나 바꿔야 합니다.

이미 Claude나 ChatGPT 안에서 많은 일을 하고 있다면, 이제 더 짧은 방법이 있습니다. Model Context Protocol(MCP)을 쓰면 어시스턴트가 외부 도구를 직접 호출할 수 있습니다. 즉, 이미 나누고 있는 대화 안에서 검증을 할 수 있습니다.

## MCP란 무엇인가

MCP는 AI 어시스턴트가 외부 서비스와 통신하는 방법을 정한 규격입니다. Anthropic이 2024년 말에 발표했으며, 그 뒤 Claude 외의 많은 서비스에서도 채택되었습니다. 플러그 규격과 같은 것으로 생각하면 이해하기 쉽습니다. MCP가 나오기 전에는 어시스턴트마다 도구별로 전용 연동을 만들어야 했습니다. 지금은 서비스가 MCP 서버 하나를 공개하면, 규격을 따르는 모든 클라이언트가 그 서버를 사용할 수 있습니다.

검증 도구라면 필요한 기능이 많지 않습니다. 요청할 일은 몇 가지뿐입니다. 이 주소를 확인하기, 이 리스트를 확인하기, 자세한 내역을 보여 주기, 남은 크레딧을 알려 주기입니다. Giggal.ai는 바로 이 기능을 세 가지 도구 `verify_emails`, `get_verification_details`, `get_credit_balance`로 제공합니다.

API와 다르게 느껴지는 이유는 호출을 직접 작성하지 않기 때문입니다. 어차피 입력하려던 문장으로 원하는 것을 말하면, 어시스턴트가 어떤 도구를 어떤 인수로 호출할지 알아서 정합니다.

## 적합한 용도와 적합하지 않은 용도

한계를 미리 솔직하게 알면 실망할 일이 줄어듭니다.

이 방법은 대화 안에서 이미 하고 있는 더 큰 작업의 한 단계로 검증이 필요할 때 적합합니다. 콘퍼런스 참가자 리스트를 붙여 넣고, 아웃리치 메일을 쓰기 전에 쓸 수 없는 주소를 빼고 싶은 경우입니다. 가입 절차를 디버깅하면서 특정 주소가 실제로 있는지 알고 싶은 경우입니다. 시퀀스를 작성하면서, 확정하기 전에 대상 기업 담당자 12명의 주소를 확인하고 싶은 경우입니다. 이런 경우에는 다른 방법을 쓰려면 대화를 떠나야 하므로, 도구 호출이 실제로 더 빠릅니다.

200,000행짜리 리스트를 정리하는 데는 적합하지 않습니다. 이는 대량 업로드나 API로 할 작업입니다. 채팅 인터페이스로 처리하면 대기 시간이 길어지고 토큰이 많이 들 뿐, 얻는 것이 없습니다. 이런 작업에는 대시보드나 REST 엔드포인트를 쓰십시오. 그러려고 있는 기능입니다.

## 설정 방법

Giggal.ai 계정과 API 키가 필요합니다. 키는 앱의 “Settings”가 아니라 “Developer API” 탭에 있습니다. 사소한 점이지만, 생각보다 자주 헷갈리는 부분입니다.

서버는 원격 서버이므로 설치할 것도 없고 SDK도 필요하지 않습니다. 주소는 `https://mcp.giggal.ai/mcp`이며, API 키로 인증합니다.

Claude Desktop에서는 “Settings”를 열고 “Connectors”에서 이 URL을 가리키는 사용자 지정 커넥터를 추가합니다. Claude Code에서는 `claude mcp add`로 같은 서버를 추가합니다. Cursor와 VS Code는 모두 프로젝트 또는 사용자 디렉터리에 있는 JSON 설정 파일에서 MCP 서버를 읽습니다. 이 파일의 형식과 정확한 설정 예시는 [MCP 페이지](/mcp)에 있습니다. ChatGPT는 이 기능을 사용할 수 있는 요금제에서 커넥터 설정을 통해 원격 MCP 서버를 지원합니다.

연결하면 어시스턴트가 세 가지 도구를 표시하며, 바로 요청을 시작할 수 있습니다.

## 실제 사용 모습

특별한 표현은 필요하지 않습니다. 다음과 같은 요청이 모두 작동합니다.

- hello@stripe.com을 검증하고 실제 메일함인지 알려 줘
- 웨비나 가입자 주소 11개야. 어떤 주소가 반송될지 확인해 줘
- 이 중에서 캐치올 도메인은 어떤 거야? 메일함은 실제로 있어?
- 이걸 실행하기 전에 검증 크레딧이 얼마나 남았는지 알려 줘

어시스턴트는 `verify_emails`를 호출하고, 주소별 결과를 받아 답변에서 설명합니다. 리스트에 대해 물었다면 같은 대화에서 이어서 요청할 수 있습니다. 무효인 주소를 모두 빼고, 남은 주소를 도메인별로 묶고, 발송 도구에 바로 붙여 넣을 수 있는 CSV 블록으로 출력해 달라고 요청하면 됩니다. 이 후반부가 이 방법을 쓸 가치가 있는 부분입니다. 어시스턴트가 이미 데이터를 가지고 있으므로, 다시 주고받지 않고도 데이터를 정리할 수 있기 때문입니다.

## 여기서는 캐치올 처리가 평소보다 더 중요합니다

B2B 리스트의 약 30%는 실제로 있든 없든 모든 주소의 메일을 받는 도메인에 있습니다. 이를 캐치올(catch-all) 도메인이라고 합니다. 대부분의 검증 도구는 이런 주소에 risky 또는 accept-all(모든 주소 수신) 라벨을 붙여 돌려줍니다. 판단할 수 없었다는 뜻입니다.

이 라벨은 대시보드에서도 다루기 불편합니다. 대화에서는 더 불편합니다. 어시스턴트는 받은 결과를 그대로 전하므로, 주소 11개 중 4개가 불확실하다는 답변을 받게 됩니다. 질문하기 전과 똑같은 상태입니다. Giggal.ai는 이런 주소를 유효 또는 무효로 판정하며, 저희가 감지하는 보안 이메일 게이트웨이 15종 뒤에 있는 메일함도 판정합니다. 그래서 어시스턴트가 받는 결과는 “모르겠다”가 아니라 실제 답입니다.

## 비용과 기본적인 주의 사항

MCP를 통한 검증도 다른 곳과 같은 크레딧을 사용합니다. 주소 하나를 검증할 때마다 크레딧 1개가 동일하게 사용되며(캐치올 주소와 SEG로 보호되는 주소 포함), 무료 플랜은 카드 없이 크레딧 1,000개를 제공합니다. 크레딧은 만료되지 않습니다.

주의 사항은 간단합니다. 어시스턴트는 요청한 대로 실행하며, 의도보다 큰 작업도 실행합니다. 큰 작업 전에는 크레딧 잔액을 먼저 물어보고, 내용을 확인하지 않은 파일을 지정하기보다 주소를 직접 붙여 넣으십시오. 둘 다 검증에만 해당하는 이야기는 아니지만, 사용량에 따라 요금이 드는 API에서는 실수했을 때 평소보다 더 곤란합니다.

## 설정할 가치가 있는가

거의 매일 Claude나 ChatGPT를 열고 이메일 리스트가 업무의 일부라면, 설정은 약 2분이면 끝나고 손으로 하던 단계 하나가 사라집니다. 검증이 한 달에 한 번 브라우저에서 하는 대량 작업이라면 대시보드가 실제로 더 나은 도구이며, 이 방법을 써도 크게 달라지지 않습니다.

각 클라이언트의 설정 방법과 설정 예시는 [MCP 페이지](/mcp)에 있습니다. 스크립트로 처리하고 싶다면 [API 레퍼런스](/public/docs)에서 같은 작업을 REST로 하는 방법을 볼 수 있습니다.
