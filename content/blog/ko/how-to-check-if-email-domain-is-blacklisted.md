이메일 운영에서 도달률이 갑자기 무너지는 것만큼 큰 문제는 많지 않습니다. 어느 날은 이메일 캠페인의 반응이 평소와 같습니다. 다음 날에는 오픈율이 0에 가깝게 떨어지고, 답장이 사라지고, 발송 대기열에 거부 메시지가 쌓입니다.

```text
550 5.7.1 Service unavailable; client [198.51.100.24] blocked using zen.spamhaus.org
554 5.7.1 Access denied; sender IP listed in Barracuda Reputation Network
```

수신 메일 서버가 제목이나 본문을 보기도 전에 메시지를 거부한다면, 발송 IP 주소나 도메인이 DNS 기반 블랙홀 리스트(DNSBL)에 올라간 것입니다. DNSBL은 흔히 이메일 블랙리스트 또는 RBL이라고 부릅니다.

블랙리스트 등재는 일시적인 콘텐츠 필터가 아닙니다. 네트워크 수준의 직접 차단입니다. Google Workspace, Microsoft 365, Yahoo Mail, 기업용 메일 게이트웨이 같은 주요 수신 네트워크는 처음 SMTP 연결을 맺는 단계에서 이 실시간 데이터베이스를 조회합니다. 발송자의 IP나 도메인이 등재되어 있으면 연결은 그 자리에서 끊깁니다.

이 글에서는 이메일 블랙리스트의 작동 방식, 도메인이나 IP가 주요 스팸 방지 데이터베이스에 올라 있는지 확인하는 방법, 블랙리스트 해제 요청을 받아들여지게 하는 방법, 다시 등재되지 않도록 발신자 평판을 지키는 방법을 설명합니다.

## 블랙리스트 차단과 스팸 필터의 차이

문제를 해결하기 전에, 블랙리스트에 등재된 것인지 수신 측 스팸함으로 분류된 것인지 먼저 구분하면 도움이 됩니다.

| 특징 | DNSBL / RBL 블랙리스트 | 메일함 제공업체의 스팸 필터 |
| --- | --- | --- |
| **판단 시점** | 처음 SMTP 연결 단계 | 전달 후 분석 단계(받은편지함 분류) |
| **서버 응답** | 하드 바운스(코드 `550` 또는 `554`) 또는 연결 끊김 | 코드 `250 OK`로 수락 |
| **수신자에게 보이는 결과** | 수신자가 이메일을 받지 못함 | 이메일이 수신자의 스팸함에 들어감 |
| **적용 범위** | 해당 DNSBL을 사용하는 모든 메일 서버 | 메일함 제공업체 한 곳(예: Gmail만) |
| **주요 원인** | 스팸 트랩에 발송, 높은 반송률, 오픈 릴레이 | 낮은 사용자 참여도, 스팸성 문구, SPF/DKIM 누락 |
| **해결 방법** | 블랙리스트 운영자에게 정식 해제 요청 | 도메인 워밍업, 리스트 정리, 평판 회복 |

메시지가 스팸함에 들어가지만 메일 서버 로그의 전송 상태가 `250 OK`라면, 도메인은 DNSBL에 등재되지 않은 것입니다. 이 경우 수신 측 메일함 제공업체가 자체 알고리즘의 평판 점수로 메시지를 분류하고 있습니다.

메일 서버가 특정 블랙리스트 호스트 이름을 언급하는 하드 거부를 받는다면, DNSBL에 실제로 등재된 상태이며 바로 조치해야 합니다.

## 이메일 도메인이나 IP가 블랙리스트에 올랐는지 확인하는 방법

블랙리스트 확인은 DNSBL 서버를 조회해 발송 IP나 도메인에 등재 기록이 있는지 보는 작업입니다. 여러 RBL을 한 번에 검사하는 자동 도구를 쓰거나, 터미널에서 DNS를 직접 조회해 확인할 수 있습니다.

### 1. 여러 RBL을 한 번에 검사하는 자동 도구

여러 RBL을 조회하는 서비스는 공개 블랙리스트 수십 개를 몇 초 안에 동시에 조회합니다. 믿을 만한 무료 도구는 다음과 같습니다.

- **MXToolbox Blacklist Check**: 발송 IP나 도메인 이름을 100개가 넘는 DNSBL에서 검사합니다.
- **DNSChecker Email Blacklist**: 50개가 넘는 DNSBL과 SURBL 데이터베이스를 동시에 빠르게 조회합니다.
- **MultiRBL (valli.org)**: 개발자용 경량 조회 도구로, 200개가 넘는 블랙리스트를 조회합니다.

검사하려면 발송 IP 주소나 발송 도메인(예: `company.com`)을 입력하십시오. 발송 IP 주소는 사무실 Wi-Fi의 IP가 아니라 메일 서버의 IP입니다.

```youtube
wOIJHhHZt04
동영상: [How To Use Email Blacklist Checker or Spam Database Lookup Tool](https://www.youtube.com/watch?v=wOIJHhHZt04)(InboxAlly: Mastering Email Deliverability)
```

### 2. 명령줄에서 DNSBL 직접 확인하기(시스템 관리자용)

자동 조회 웹 도구는 편리합니다. 하지만 `dig`나 `nslookup`으로 직접 조회하면 블랙리스트 운영자의 권한 있는 네임 서버에서 캐시되지 않은 원래 결과를 바로 받을 수 있습니다.

DNS 기반 블랙리스트는 [IETF RFC 5782](https://datatracker.ietf.org/doc/html/rfc5782)에 따라 IP 주소를 거꾸로 적는 방식을 사용합니다. 블랙리스트를 직접 조회하는 방법은 다음과 같습니다.

1. 발송 IPv4 주소의 네 부분 순서를 거꾸로 바꿉니다. 예를 들어 메일 서버 IP가 `198.51.100.24`라면 거꾸로 바꾼 문자열은 `24.100.51.198`입니다.
2. 뒤에 DNSBL의 루트 도메인(예: `zen.spamhaus.org`)을 붙입니다.
3. `dig`로 일반 `A` 레코드 DNS 조회를 실행합니다.

```bash
# Query Spamhaus ZEN for IP 198.51.100.24
dig +short 24.100.51.198.zen.spamhaus.org

# Query Barracuda Reputation Block List (BRBL)
dig +short 24.100.51.198.b.barracudacentral.org

# Query SpamCop (SCBL)
dig +short 24.100.51.198.bl.spamcop.net
```

#### 반환 코드 해석

- **응답 없음 / `NXDOMAIN`**: IP에 문제가 없습니다. 블랙리스트에 해당 주소의 부정적인 기록이 없습니다.
- **`127.0.0.X` 응답**: IP가 등재되어 있습니다. 마지막 숫자가 등재 유형을 나타냅니다.

```text
127.0.0.2 -> SBL (Spamhaus Block List: Verified spam source or trap hit)
127.0.0.4 -> XBL (Exploit Block List: Compromised server, malware, or open proxy)
127.0.0.10 -> PBL (Policy Block List: Residential/dynamic IP that should not send direct MX mail)
```

위 응답의 뜻은 다음과 같습니다. `127.0.0.2`는 SBL로, 확인된 스팸 발송원이거나 스팸 트랩에 발송한 경우입니다. `127.0.0.4`는 XBL로, 해킹된 서버, 악성 코드, 오픈 프록시인 경우입니다. `127.0.0.10`은 PBL로, MX 메일을 직접 보내면 안 되는 가정용 또는 동적 IP인 경우입니다.

발송 IP가 아니라 도메인 이름이 도메인 블랙리스트(DBL)에 올랐는지 확인하려면 도메인 이름을 직접 조회하십시오.

```bash
# Query Spamhaus Domain Blocklist (DBL)
dig +short company.com.dbl.spamhaus.org
```

`127.0.1.2` 응답은 도메인 이름 자체가 스팸 도메인으로 등재되었다는 뜻입니다. 이 경우 발송 IP 주소를 바꿔도 메일 제공업체가 메시지를 거부합니다.

## 실제로 중요한 블랙리스트 5개

인터넷에는 공개 및 비공개 이메일 블랙리스트가 수백 개 있습니다. 하지만 이메일이 수신자의 받은편지함에 도달하는지에 실제로 영향을 주는 것은 몇 개뿐입니다.

개인이 운영하는 소규모 블랙리스트나, 돈을 받고 삭제해 주는 악용 서비스 같은 많은 작은 블랙리스트는 주요 메일함 제공업체가 사용하지 않습니다. 아무도 쓰지 않는 잘 알려지지 않은 리스트에 등재되어도 도달률에는 영향이 없습니다.

다음 주요 리스트에 집중하십시오.

### 1. Spamhaus (ZEN: SBL, XBL, CSS, DBL)

Spamhaus는 세계에서 영향력이 가장 큰 스팸 방지 조직입니다. Spamhaus의 데이터는 전 세계 메일함 30억 개 이상을 보호합니다. 여기에는 주요 통신 네트워크, Fortune 500 기업의 이메일 게이트웨이, 개인용 이메일 제공업체가 포함됩니다.

- **SBL (Spamhaus Block List)**: 확인된 스팸 발송원, 수신 동의를 확인하지 않은 메일링 리스트, 스팸 트랩에 발송하는 발송자를 대상으로 합니다.
- **XBL (Exploit Block List)**: 외부 공격 코드, 봇넷, 악성 코드에 감염된 서버를 대상으로 합니다.
- **DBL (Domain Block List)**: 스팸 메시지, 피싱 미끼, 방탄 호스팅(bulletproof hosting)에서 발견된 도메인을 등재합니다.
- **ZEN**: SBL, SBLCSS, XBL, PBL 기록을 합친 통합 영역입니다.

Spamhaus 등재는 즉시 대응해야 하는 운영 비상 상황입니다. 전 세계 주요 기업 메일 서버와 인터넷 서비스 제공업체에서 전송이 차단됩니다.

### 2. Barracuda (BRBL)

Barracuda Reputation Block List(`b.barracudacentral.org`)는 Barracuda Networks가 관리합니다. 기업 네트워크 안에서 작동하는 수천 대의 Barracuda Email Security Gateway 장비에서 모은 트래픽 데이터로 만들어집니다.

B2B 콜드메일이나 기업 대상 마케팅 이메일을 보낸다면, Barracuda 등재는 바로 반송률 상승으로 이어집니다. 온프레미스나 클라우드에서 Barracuda 보안 필터를 쓰는 기업 수신자에게서 반송이 발생합니다.

### 3. SpamCop (SCBL)

SpamCop은 신고 기반 블랙리스트 중 가장 오래된 것 가운데 하나(`bl.spamcop.net`)를 운영합니다. 수신자가 이메일을 스팸으로 신고하거나 자동 트랩이 원치 않는 메시지를 받으면 발송자가 자동으로 등재됩니다.

Spamhaus와 달리 SpamCop 등재는 자주 바뀌고 오래가지 않습니다. 스팸 신고가 기준 아래로 떨어지면 보통 24~48시간 안에 자동으로 해제됩니다.

### 4. Invaluement (ivmURI, ivmSIP)

Invaluement는 기업용 상업 평판 데이터베이스입니다. 대량 메일을 처리하는 기업 이메일 필터와 보안 소프트웨어에서 자주 사용합니다. 스노슈 스팸(snowshoe spamming, 많은 IP 주소에 스팸을 나누어 보내는 방식)을 빠르게 찾아내고, 도메인 수준의 URL 평판을 추적하는 것으로 알려져 있습니다.

### 5. UCEPROTECT Level 3는 무시해도 되는 이유

여러 RBL을 조회하는 도구를 쓰다 보면, **UCEPROTECT Level 3**에 빨간색 등재 표시가 나와 당황하는 발송자가 많습니다.

UCEPROTECT Level 3는 개별 발송 IP가 아니라 서브넷 전체와 자율 시스템 번호(ASN) 전체를 등재합니다. 같은 클라우드 호스팅 업체(DigitalOcean, AWS, Linode, Hetzner 등)의 관련 없는 다른 고객이 스팸을 보내면, UCEPROTECT는 그 호스팅 업체 전체에서 문제없는 주변 IP 주소 수천 개를 함께 등재합니다.

이렇게 관련 없는 IP까지 넓게 등재하기 때문에, Google, Microsoft, Yahoo 같은 주요 이메일 제공업체는 전송 판단에 UCEPROTECT Level 3를 사용하지 않습니다. 도달률 엔지니어와 포스트마스터도 Level 3 등재는 대부분 무시합니다. 삭제해 주는 대가로 돈을 요구하는 서비스에 해제 비용을 내지 마십시오.

## 블랙리스트 해제 단계별 절차

블랙리스트 확인 결과 주요 데이터베이스에 실제로 등재되어 있다면, 다음 네 단계 복구 절차를 따르십시오.

```
[ Step 1: Halt Outbound Queues ]
             │
             ▼
[ Step 2: Audit Root Cause & Logs ]
             │
             ▼
[ Step 3: Implement Technical Fixes ]
             │
             ▼
[ Step 4: Submit Delisting Request ]
```

위 그림의 네 단계는 발송 대기열 중지, 근본 원인과 로그 점검, 기술적 문제 수정, 해제 요청 제출입니다.

### 1단계: 발송을 즉시 중지

메일 서버가 아직 메시지를 보내고 있을 때는 해제 요청을 제출하지 마십시오. 서버가 계속 스팸 트랩에 발송하거나 반송을 만들고 있는 상태에서 삭제를 요청하면 요청은 거부됩니다. 그리고 IP는 협조하지 않는 상습 위반자로 표시됩니다.

- 자동 발송 시퀀스와 콜드메일 캠페인을 일시 중지하십시오.
- 메일 서버 대기열(Postfix의 `mailq`)을 확인해, 해킹된 계정이나 취약한 문의 폼 때문에 스팸이 대량으로 나가고 있지 않은지 살펴보십시오.

### 2단계: 근본 원인을 찾아 수정

블랙리스트는 원인이 된 사건 없이 IP를 등재하지 않습니다. 로그와 인프라를 검토해, 다음 네 가지 흔한 원인 중 무엇 때문에 등재되었는지 확인하십시오.

1. **프리스틴 스팸 트랩(pristine spam trap)**: 사람이 한 번도 소유한 적 없는 주소로 메일을 보낸 경우입니다. 이런 주소는 웹 스크래핑 봇을 잡으려는 목적으로만 공개됩니다. 리드 리스트를 구매했거나 웹사이트 연락처 페이지를 검증 없이 스크래핑했다면, 프리스틴 스팸 트랩에 발송했을 가능성이 높습니다.
2. **높은 반송률**: 발송 반송률이 2.0%~5.0%를 넘은 경우입니다. 연락처 기록이 오래되었거나, 검증되지 않았거나, 지어낸 것이라는 신호입니다.
3. **유출된 계정 정보**: 서버의 사용자 계정이 해킹되어 피싱이나 스팸 메시지를 중계하는 데 사용된 경우입니다.
4. **인증 누락**: 도메인에 정렬된 SPF와 DKIM 레코드가 없어, 제3자가 도메인 이름을 위조할 수 있는 경우입니다.

### 3단계: 주요 운영 기관에 삭제 요청 제출

문제를 해결하고 로그에 이상이 없으면, 공식 포털에서 직접 정식 해제 요청을 제출하십시오.

#### Spamhaus 해제
1. 공식 [Spamhaus IP and Domain Reputation Checker](https://check.spamhaus.org/)로 이동합니다.
2. 등재된 IP 주소나 도메인을 입력합니다.
3. Spamhaus가 제공하는 정확한 등재 코드와 설명을 확인합니다.
4. **Request Removal** 버튼을 클릭하고 확인 양식을 작성합니다.
5. 해당 도메인에서 실제로 쓰는 관리자 이메일 주소를 입력합니다. 문제없는 발송자의 첫 해제 요청은 보통 1~4시간 안에 처리됩니다.

#### Barracuda 해제
1. [Barracuda Central Reputation System](https://www.barracudacentral.org/lookups)에 접속합니다.
2. 메일 서버 IP 주소를 입력합니다.
3. **Barracuda Removal Request** 양식으로 이동합니다.
4. 연락처 정보를 입력하고, 어떤 수정 조치를 했는지 사실대로 분명하게 설명합니다. 보통 12~24시간이 걸립니다.

#### SpamCop 해제
- [SpamCop](https://www.spamcop.net/bl.shtml)은 직접 요청이 필요한 경우가 드뭅니다. 문제가 된 메일 발송을 중지했다면, SpamCop은 마지막 신고 후 24~48시간이 지나면 등재를 자동으로 해제합니다.

### 해제 요청에 쓸 내용과 쓰면 안 되는 내용

해제 요청은 경험 많은 네트워크 엔지니어가 검토합니다. 요청을 어떻게 쓰느냐에 따라 승인 여부가 달라집니다.

> **이렇게 쓰지 마십시오:**  
> *“저희는 정상적인 회사이며 이번 일은 긴급한 착오입니다. 귀사 때문에 손실이 발생하고 있습니다. 저희 IP를 즉시 삭제해 주십시오.”*  
> (기술적으로 안심할 근거를 전혀 주지 않으므로 처리 순위가 뒤로 밀립니다.)

> **이렇게 쓰십시오:**  
> *“10월 24일에 업로드된 검증되지 않은 마케팅 리스트 때문에 반송과 스팸 신고가 급증한 것을 확인했습니다. 발송은 즉시 중지했습니다. 검증되지 않은 기록을 모두 삭제했고, 무효 주소와 일회용 주소를 지우는 발송 전 자동 리스트 정리를 도입했으며, SPF와 DKIM 정렬을 확인했습니다. 현재 발송 대기열에는 문제가 없습니다.”*

## 블랙리스트에 다시 오르지 않는 방법

블랙리스트에서 해제되는 것은 절반에 불과합니다. 발송 습관을 바꾸지 않으면 며칠 안에 도메인이 같은 블랙리스트에 다시 오릅니다.

발신자 평판을 지키려면 다음 세 가지를 계속 관리해야 합니다.

### 1. 엄격한 이메일 인증 적용

인증되지 않은 메일 발송은 도메인 위조에 취약합니다. 스패머가 피싱 캠페인의 `From:` 헤더에 회사 도메인 이름을 쓰면, 도메인 평판이 떨어집니다.

- **SPF (Sender Policy Framework)**: 도메인을 대신해 메일을 보낼 수 있는 메일 서버를 명시적으로 지정합니다. 무료 [SPF 검사 도구](/spf-checker)로 설정을 확인하십시오.
- **DKIM (DomainKeys Identified Mail)**: 발송하는 모든 메시지에 2048비트 키로 암호 서명을 합니다. [DKIM 생성기](/dkim-generator)로 DNS 키를 만들 수 있습니다.
- **DMARC**: 도메인에서 보낸 것처럼 꾸민 인증되지 않은 메시지를 거부하도록 수신 서버에 지시합니다.

### 2. 반송률과 SMR 지표 모니터링

반송률을 반드시 2.0% 미만으로 유지하십시오. 반송률이 3.0%를 넘으면 리스트 관리가 부실하다는 신호이고, 5.0%를 넘으면 기업용 필터에서 자동으로 블랙리스트에 오릅니다.

- [반송률 계산기](/bounce-rate-calculator)로 과거 전송 지표를 측정하고 비교하십시오.
- [하드 바운스와 소프트 바운스의 차이](/blog/hard-bounce-vs-soft-bounce)를 읽고, 일시적인 서버 문제와 영구적인 무효 주소를 구분하십시오.

### 3. 발송 전에 모든 리드 리스트 정리

이메일 블랙리스트 등재의 85% 이상은 프리스틴 스팸 트랩에 발송하거나, 삭제된 메일함에 반복해서 발송한 데서 비롯됩니다.

스크래핑한 잠재 고객 리스트, 오래된 CRM 데이터베이스, 웨비나 가입자 리스트에는 오타 도메인, 임시 일회용 이메일, 방치된 주소가 자주 섞여 있습니다. 방치된 주소는 재활용 스팸 트랩으로 바뀌기도 합니다.

연락처 리스트를 발송 플랫폼이나 콜드메일 도구로 가져오기 전에, 별도의 검증 단계를 거쳐 주소를 검증하십시오. 주소 하나는 [무료 이메일 유효성 검사 도구](/email-checker)로 테스트하고, 일회용 도메인은 [일회용 이메일 판별 도구](/disposable-email-checker)로 찾아낼 수 있습니다. 리스트를 정리하면 메일 서버가 발송하기 전에 없는 도메인, 형식 오류, 임시 이메일 제공업체, 알려진 트랩 네트워크를 걸러낼 수 있습니다.

## 자주 묻는 질문

### 블랙리스트 해제가 적용되기까지 얼마나 걸립니까?
운영자가 해제 요청을 승인하면, 운영자의 권한 있는 DNSBL 서버는 거의 바로 업데이트됩니다. 하지만 수신 메일 서버는 DNS 기록을 로컬에 캐시합니다. 수신 서버의 DNS TTL(Time to Live) 설정에 따라 다르지만, 모든 네트워크에서 정상 전송이 다시 이루어지기까지 보통 2~24시간이 걸립니다.

### Google Workspace나 SendGrid 같은 평판 좋은 ESP를 써도 도메인이 블랙리스트에 오를 수 있습니까?
네. 이메일 서비스 제공업체(ESP)는 인프라를 관리하지만, 어떤 주소로 보낼지는 여전히 발송자의 책임입니다. Google Workspace나 SendGrid로 콜드메일이나 검증하지 않은 대량 리스트를 보내다가 스팸 트랩에 발송하면, Spamhaus가 발송 도메인을 도메인 블랙리스트(DBL)에 등재할 수 있습니다. 그러면 어떤 발송 플랫폼을 쓰든 메일이 거부됩니다.

### 도메인이 블랙리스트에 오르면 도메인 이름을 바꿔야 합니까?
아니요. 블랙리스트에 오른 도메인을 버리고 새 도메인을 등록하는 것은 잘못된 선택입니다. 새 도메인은 발신자 평판이 전혀 없어서, 메일함 제공업체의 엄격한 발송 속도 제한과 그레이리스팅을 받습니다. 기존 도메인에서 근본 원인을 고치고, 구독자 리스트를 정리하고, 정식 해제 절차를 마치는 편이 더 빠르고 장기적인 도달률에도 좋습니다.
